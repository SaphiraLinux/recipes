# UNDEF-flagged lines and their contract (POSIX SUSv3 wordexp:
# WRDE_UNDEF = "Report error on an attempt to expand an undefined shell
# variable"; WRDE_BADVAL = "Reference to undefined shell variable when
# WRDE_UNDEF is set in flags"):
# - lines 3-6,8,10 (metachar/unbalanced inputs) are rejected by the
#   NOCMD scanner first (BADCHAR/CMDSUB/SYNTAX): UNDEF never engages.
#   Expectations unchanged by UNDEF support.
# - line 7 ('$UNSET ${ $UNSET') is scanner-SYNTAX with alt BADCHAR:
#   unchanged (scanner first).
# - line 64 ('"${X-"$"Y}"', WRDE_UNDEF) passes the scanner and the
#   Class-B checker (0021) reports BADVAL: the quote-first "$" pair is
#   transparent, so Y is an expansion attempt on an unset variable.
#   Verified against bash (`set -u' reports `Y: unbound variable'),
#   homer glibc 2.44 (BADVAL, ret 3) and the 0003-style checker.
#   alt 0 covers UNDEF-less builds (pristine musl expands to empty).
#   Genuine locale controls stay silent: `$"foo"' expands to `foo'
#   with no error under `set -u', and in-`dq` `$"` stays literal.
# - line 65 ('"${X-"$"{Y"}"}"', WRDE_UNDEF) is NOCMD-rejected
#   (BADCHAR from every implementation, pre-existing, unchanged):
#   the shell cannot parse the shape at all, so UNDEF never engages.
# - line 9 ('"$UNSET 'unterminated $UNSET", unbalanced quote) reaches
#   no expansion: the shell fails to parse before any variable is
#   expanded, so WRDE_SYNTAX is correct and takes precedence over any
#   UNDEF finding. (During analysis this line was briefly misread as a
#   balanced input implying BADVAL; direct byte-exact testing shows
#   pristine, Sinew r13/r14, 0003-style and forkless-native
#   implementations all agree on SYNTAX here, matching 'sh -u'
#   itself, which reports the parse failure rather than an unbound
#   variable.)
# 0023 classification (2026-11-12, POSIX shell-equivalence oracle:
# /bin/sh is bash here, the shell wordexp invokes; glibc 2.44 on homer
# corroborates but does not define):
# - spaced arithmetic close ('$((1 + 2 ) )') executes as $(...) in the
#   shell: the scanner now requires adjacent '))' (missed execution
#   closed). Quoted spans inside arithmetic ('$(("1"))') expand (value
#   1) but their content is still scanned: '$(' or backquote inside
#   blocks. Bare '{' in a brace word is literal ('${X-{}}' -> '{}').
# - shell-proven want corrections: 80/81 SYNTAX (shell rejects, alt 0
#   keeps glibc-compat green), 99/100 CMDSUB (shell executes), 108/109
#   0 (shell+glibc+scanner agree), 114 0 (shell expands to 1; glibc says
#   SYNTAX, shell is the oracle).
# - remaining known gaps (fail closed, documented, not fixed here):
#   23 ANSI-escape span over-blocks; 65 three-way split (shell clean,
#   glibc SYNTAX); 72 nested-unit quote-state divergence; 78 shell
#   executes but both libcs say BADCHAR (want CMDSUB pins the truth);
#   105 arithmetic-paren swallows textual '$(cmd)' (both say CMDSUB).
#   KNOWN DIVERGENCE (verified 2026-11-12 on homer/glibc 2.44):
#   glibc returns WRDE_BADVAL here — its native UNDEF check fires
#   before shell parsing. Sinew follows POSIX shell equivalence
#   (parse first, then expand), not glibc, on malformed input.
#   Verified 2026-11-12 against installed r14 on Egg and Minimer.
# 0033 close-quote fix (2026-11-14, canary-proven on r19 + /bin/sh):
#   vec-67 ('"${X-"$"(echo x)}"') and vec-68 ('$((${X-"$"(echo + 2)}))')
#   both EXECUTE despite WRDE_NOCMD (the scanner read "$" as
#   quote-opening while the shell re-parses it as quote-closing,
#   exposing live '$('). Both now want CMDSUB (fail-closed, accurate);
#   the old want=0 blessed the execution. S7-style valid arithmetic
#   ('$"((1+1))') still evaluates via arith_ok and stays clean.
