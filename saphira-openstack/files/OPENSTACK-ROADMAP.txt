saphira-openstack: native OpenStack dependency roadmap
=====================================================

This records the VERIFIED native APK dependency graph toward Keystone and
the wider OpenStack service set, and what remains. It is engineering
status, not a promise: entries move from MISSING to packaged only when a
real recipe exists in /recipes.

The installer never claims a service is deployable while its recipes are
missing; the component catalog marks every unported service PENDING.

Porting order (repository-first, dependency-before-consumer)
------------------------------------------------------------

  1. oslo.* foundation, leaf-first: DONE (keystone closure).
  2. keystonemiddleware: DONE.
  3. keystone 30.0.0 (gunicorn WSGI, mariadb-client-side): recipe
     exists, building.
  4. glance 33.0.0 + placement 16.0.0 + their 37-recipe leaf wave:
     recipes exist, building.
  5. backing infrastructure: rabbitmq (+ erlang), memcached.
  6. nova 34.0.0 -> neutron 29.0.0 -> cinder 29.0.0 -> horizon 27.0.0,
     each with the layer above. All versions pinned to stable/2026.2
     upper-constraints before porting (see wave-1 method).

Conventions every recipe follows
--------------------------------

  * pkgname=python-<pypi-name> (or the de-prefixed native name already
    established, e.g. idna, certifi);
  * source=<pinned sdist URL> + sha256=<64-hex>, with the archive
    vendored at files/<basename> and a files/<basename>.sha256 sidecar;
  * recipe_build is a no-op; recipe_install runs
    `python3 -m pip install --no-deps --no-build-isolation --no-compile
     --root "$PKGDEST" --prefix /usr "$SRC"` into system site-packages;
  * no unpinned network installation at build time: the vendored archive
    is the only input;
  * pkgrel>=1; repo=saphira; license is the upstream SPDX identifier.

Deferred upstream dependencies recorded per recipe
--------------------------------------------------

  python-webob    -> python-legacy-cgi
  python-routes   -> python-repoze-lru
  python-alembic  -> python-tomli

These are noted in each recipe as comments; they are not depends= entries
until their own recipes exist, so every recipe here resolves today.
